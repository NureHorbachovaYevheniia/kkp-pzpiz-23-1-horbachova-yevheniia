АВТЕНТИФІКАЦІЯ, ВЕБЗАСТОСУНОК, ІНОЗЕМНА ЛЕКСИКА, НАВЧАЛЬНА ПЛАТФОРМА, НАВЧАЛЬНІ КАРТКИ, СТАТИСТИКА НАВЧАННЯ, ТЕСТУВАННЯ ЗНАНЬ, ESP32, EXPRESS, JAVASCRIPT, JWT, NODE.JS, REST API, SQLITE, VITE, WOKWI.


Об’єктом розробки є програмна система для вивчення іноземної лексики, організації навчального процесу та контролю результатів навчання учнів.
Метою розробки є проєктування та реалізація вебплатформи, яка забезпечує створення навчальних класів, наборів слів, навчальних карток, призначення завдань, проходження тестів, збереження результатів і перегляд статистики успішності. Система призначена для використання викладачами, учнями та адміністраторами, а також передбачає демонстраційний IoT-модуль для роботи з навчальними картками на окремому пристрої.
Методи розробки програмної системи базуються на використанні клієнт-серверної архітектури, REST API та модульної організації програмного коду. Серверну частину реалізовано за допомогою Node.js та Express. Для зберігання даних використано реляційну базу даних SQLite. Автентифікація та авторизація користувачів реалізовані з використанням JWT-токенів і розмежуванням доступу відповідно до ролей. Клієнтську частину створено як SPA-застосунок за допомогою Vite та Vanilla JavaScript. Додатково реалізовано демонстраційний IoT-модуль у середовищі Wokwi на базі ESP32 та OLED-дисплея.
У результаті розробки спроєктовано та реалізовано навчальну платформу Learnly, яка дозволяє організувати процес вивчення іноземної лексики в цифровому середовищі. Система підтримує роботу з ролями користувачів, навчальними класами, наборами слів, картками, завданнями, тестами, статистикою навчання, локалізацією інтерфейсу та обмеженнями безкоштовного плану. Реалізований IoT-модуль демонструє можливість використання навчального функціоналу на пристроях з обмеженим інтерфейсом.


AUTHENTICATION, WEB APPLICATION, FOREIGN VOCABULARY, LEARNING PLATFORM, FLASHCARDS, LEARNING STATISTICS, KNOWLEDGE TESTING, ESP32, EXPRESS, JAVASCRIPT, JWT, NODE.JS, REST API, SQLITE, VITE, WOKWI.


The object of development is a software system for learning foreign vocabulary, organizing the educational process, and monitoring students’ learning results.
The goal of the development is to design and implement a web platform that provides the creation of learning classes, word sets, flashcards, assignment distribution, test completion, result storage, and learning statistics review. The system is intended for teachers, students, and administrators, and also includes a demonstration IoT module for working with flashcards on a separate device.
The methods of developing the software system are based on the use of client-server architecture, REST API, and modular code organization. The server side was implemented using Node.js and Express. The SQLite relational database was used for data storage. User authentication and authorization were implemented using JWT tokens and role-based access control. The client side was developed as a SPA application using Vite and Vanilla JavaScript. In addition, a demonstration IoT module was implemented in the Wokwi environment based on ESP32 and an OLED display.As a result of the development, the Learnly learning platform was designed and implemented.
It allows organizing the process of learning foreign vocabulary in a digital environment. The system supports user roles, learning classes, word sets, flashcards, assignments, tests, learning statistics, interface localization, and free plan limitations. The implemented IoT module demonstrates the possibility of using learning functionality on devices with a limited interface.

ВСТУП


У сучасних умовах освіта дедалі активніше переходить у цифровий формат, тому програмні системи, що допомагають організовувати навчальний процес, набувають усе більшого значення. Вони підвищують зручність навчання та сприяють ефективній взаємодії між викладачами й учнями. Особливо актуальними є платформи для вивчення іноземних мов, оскільки володіння мовами сьогодні є важливою складовою як навчання, так і подальшої професійної діяльності.
Одним із ключових етапів вивчення мови є поповнення словникового запасу, тому програмні системи для роботи з новою лексикою мають практичну цінність для багатьох категорій користувачів. Традиційно слова вивчають за допомогою паперових словників, зошитів або окремих списків, проте такий підхід не завжди забезпечує зручну перевірку знань. При такому підході викладачеві складно оперативно відстежувати успішність учнів і проводити контроль вивченої лексики, адже оцінювання кожного потребує значних витрат часу. Саме тому постає потреба у створенні цифрової системи, яка об'єднувала б навчальні матеріали та автоматизувала перевірку успішності засвоєння нових слів. 
Таким чином, розробка вебплатформи є актуальною, оскільки вона спрямована на вирішення конкретної освітньої задачі – організацію зручного, контрольованого та інтерактивного процесу навчання. Така система може використовуватися викладачами для створення навчальних матеріалів і контролю успішності, а учнями – для виконання завдань, повторення слів та самоперевірки. Окрім того, платформа буде корисною для невеликих навчальних груп, онлайн-шкіл та користувачів, які прагнуть систематизувати процес вивчення лексики самостійно.


1 АНАЛІЗ ПРЕДМЕТНОЇ ОБЛАСТІ


Предметною областю даної роботи є цифрові навчальні системи для вивчення іноземної лексики. Засвоєння слів є одним із ключових етапів оволодіння іноземною мовою, адже саме словниковий запас дозволяє користувачеві розуміти тексти, будувати речення, вести розмову та виконувати навчальні завдання. Без достатнього запасу слів навіть хороше знання граматичних правил не забезпечує повноцінної комунікації. Тому процес засвоєння лексики має бути регулярним та структурованим.
У навчальному процесі слова зазвичай групуються за темами, рівнями складності або навчальними модулями. Наприклад, окремий набір може містити лексику з тем «Їжа», «Подорожі», «Професії», «Освіта» чи «Робота». Такий підхід допомагає учням краще запам'ятовувати матеріал, оскільки слова подаються в межах певного контексту чи навчального юніту. 
Одним із поширених методів вивчення слів є використання навчальних карток. Картка, як правило, містить слово іноземною мовою та його переклад або пояснення з протилежного боку. Учень переглядає картки, намагається пригадати значення слова, а потім перевіряє себе перевертаючи картку. Такий спосіб є простим і зрозумілим, проте в цифровому форматі він може стати значно ефективнішим.


1.2 Виявлення та вирішення проблем


Навчальний процес стикається з багатьма викликами. Перш за все матеріали часто залишаються розкиданим між різними інструментами: списки слів зберігаються в документах чи на роздрукованих листах, а завдання надсилаються через месенджери або диктуються усно. Відсутність єдиного середовища ускладнює роботу і викладача, і учня. Тому перевагою єдиної системи було би обʼєднання основних дій, таких як створення наборів слів, призначення завдань, їх виконання та перегляд результатів у межах однієї платформи.
З першою проблемою тісно повʼязана складність контролю успішності. Викладач змушений вручну перевіряти завдання, підраховувати бали й аналізувати прогрес, що потребує часу залежно від кількості учнів. Через це важко проводити аналітику та збирати статистику, яка б показувала, які теми викликають найбільше труднощів та які теми варто повторити. Автоматичне збереження результатів тестування й базова інформація, така як кількість виконаних завдань, середній бал, результати окремих учнів, можуть зекономити час викладача та спрямувати його зусилля на покращення матеріалів, а не монотонну перевірку.
Окремо постає питання мотивації. Звичайні списки слів сприймаються як одноманітні, особливо коли учень не бачить власного прогресу та, не менш важливо, нагадування. Щоб допомогти з цим питанням, система може робити навчання наочним та інтерактивним: завдяки навчальним карткам, тестам і візуалізації прогресу учень може бачити, які завдання виконано, який бал отримано та чи потрібно повторити тему. Такий підхід перетворить механічне заучування на більш залучений процес. Також для кращої зручності система може надсилати нагадування та відображати дедлайни, щоб мотивувати учнів навчатись регулярно та систематично.


1.3 Аналіз аналогів програмного забезпечення


Для визначення вимог до майбутньої веб-платформи доцільно розглянути наявні програмні аналоги, щоб виявити сильні сторони вже існуючих рішень, а також визначити функції, які можна покращити чи додати.
Одним із найбільш відомих аналогів є Quizlet – онлайн-сервіс для створення та використання навчальних карток, тестів і навчальних активностей[1]. Його перевагами є простий інтерфейс, велика кількість готових наборів і можливість швидко створювати матеріали для навчання. Quizlet підходить як для самостійного навчання, так і для використання викладачами, а різні режими вивчення роблять процес запамʼятовування слів більш різноманітним та інтерактивним.
Проте недоліком Quizlet у контексті цієї роботи є те, що сервіс є універсальним і не завжди орієнтований саме на модель взаємодії «викладач – учень» у межах конкретної навчальної групи. Частина функцій обмежена або залежить від тарифного плану, а аналітика не показує викладачеві наприклад наскільки часто й регулярно учень повторював матеріал перед перевіркою. Також Quizlet не дозволяє проводити контрольні роботи для групи людей одночасно.
Іншим аналогом є Anki – програма для роботи з навчальними карткам методом інтервального повторення матеріалу[2]. Anki добре підходить для довготривалого запамʼятовування великої кількості інформації, зокрема іноземних слів, термінів, дат або визначень. Її перевагами є гнучкість, можливість створювати власні колоди карток і зосередження на тих матеріалах, які користувач знає гірше. Проте Anki більше орієнтований на індивідуальне навчання та не пропонує ніякий функціонал чи засоби контролю для вчителів та навчальних закладів.
Порівняльний аналіз аналогів показує, що кожен із розглянутих сервісів має свої переваги та вже реалізований механізм вивчення лексики за допомогою flash-карток. Проте обидва аналоги залишають значну частину контролю на ручній перевірці й не дають викладачеві наочної картини того, яка успішність кожного з учня у тих чи інших темах, та класів в загальному.

2 ПОСТАНОВКА ЗАДАЧІ


У межах комплексного курсового проєкту необхідно розробити веб-платформу, призначену для організації процесу вивчення іноземних слів. Система має забезпечувати зручну взаємодію між викладачами та учнями, підтримувати роботу з навчальними картками, призначення завдань, проходження тестів, збереження результатів і перегляд успішності.
Платформа має бути орієнтована на дві основні категорії користувачів: викладачів та учнів. Викладач повинен мати можливість створювати навчальні матеріали, формувати набори слів, додавати картки, задавати завдання учням і переглядати результати їх виконання. Учень повинен мати можливість приєднуватися до класів, переглядати призначені завдання, вивчати слова за допомогою карток, проходити тести та відстежувати власний прогрес.
Також у системі необхідно передбачити розмежування доступу відповідно до ролей користувачів. Це потрібно для того, щоб викладачі мали доступ до інструментів керування навчальним процесом, а учні — лише до функцій виконання завдань і перегляду власних результатів. Окремо може бути передбачена роль адміністратора для загального технічного контролю роботи системи.
Для виконання поставленої задачі в межах комплексного курсового проєкту необхідно:
   * сформулювати основні вимоги до майбутньої системи;
   * визначити ролі користувачів системи та їхні основні можливості;
   * спроєктувати загальну архітектуру програмного забезпечення;
   * спроєктувати структуру зберігання даних для користувачів, класів, наборів слів, навчальних карток, завдань і результатів тестування;
   * реалізувати серверну частину з REST API для обробки запитів, авторизації користувачів і роботи з даними;
   * реалізувати клієнтську частину з інтерфейсами для викладача, учня та адміністратора;
   * забезпечити можливість створення навчальних карток, формування наборів слів і призначення завдань;
   * реалізувати проходження тестів і збереження результатів навчання;
   * передбачити перегляд особистої статистики учня та статистики успішності класу для викладача;
   * забезпечити адаптивність інтерфейсу для коректної роботи системи на різних пристроях;
   * виконати тестування основних функцій системи;
Результатом виконання комплексного курсового проєкту має стати працездатна веб-платформа, яка дозволяє організувати процес вивчення іноземної лексики в цифровому середовищі.

UML-проєктування програмного забезпечення є важливим етапом розробки системи, оскільки дозволяє визначити основних користувачів, функціональні можливості та логіку взаємодії між елементами програмного продукту. Використання UML-діаграм дає змогу формалізувати вимоги до системи та представити її у вигляді зрозумілих графічних моделей.
У межах даного проєкту розробляється навчальна вебплатформа для вивчення слів за допомогою карток, навчальних наборів і тестів. Система передбачає роботу кількох типів користувачів: учня, викладача, адміністратора, а також IoT-клієнта у вигляді симулятора пристрою. Для опису проєкту використано UML діаграму прецедентів, діаграму активності та діаграму послідовності.

3.2 Проєктування архітектури ПЗ
3.2.1 Архітектурний огляд системи


Система побудована за клієнт-серверною архітектурою з REST API та трирівневою організацією: рівень представлення (веб-клієнт), рівень бізнес-логіки (сервер Node.js/Express) і рівень даних (SQLite). Серверна частина реалізована модульно — окремі модулі для автентифікації, класів, наборів слів, завдань, навчання, тестів і статистики.
Клієнт (SPA) відображає інтерфейс для учня, викладача та адміністратора і надсилає HTTP-запити на сервер. Сервер обробляє запити, виконує перевірки доступу, бізнес-логіку та роботу з базою даних, після чого повертає відповідь у форматі JSON. 
IoT-клієнт — демонстраційний модуль, що імітує навчальний пристрій на базі ESP32 та OLED-дисплея. У поточній версії він працює автономно з локальним набором слів, а в майбутньому може бути інтегрований із сервером через REST API.
Перевагами такої структури є:
   * Розділення відповідальності — інтерфейс і логіка не змішуються, їх простіше підтримувати та розширювати.
   * Доступність — система працює через браузер, без окремого встановлення на пристрої.
Масштабованість — можна змінювати клієнт або сервер незалежно, додавати нові API-ендпоінти.


3.2.2 Опис основних компонентів системи


Клієнтський рівень
Веб-клієнт (SPA) — односторінковий застосунок (JavaScript, Vite) з екранами для учня, викладача та адміністратора. Відображає інтерфейс і звертається до сервера через REST API.
IoT-клієнт — спрощений інтерфейс (iot/), що імітує навчальний пристрій. Використовує той самий API для входу, навчання та збереження прогресу.
Серверний рівень
Express Server — точка входу (index.js): HTTP-сервер, підключення маршрутів, статичні файли клієнта та IoT.
API-маршрутизатори — модулі за областями: автентифікація, класи, набори слів, завдання, навчання, тести, статистика, адміністрування.
Middleware — CORS, обмеження запитів, перевірка JWT і ролей користувача.
Допоміжні модулі — робота з БД (db.js), спільні функції (helpers.js), ліміти та початкові дані.
Рівень даних
SQLite — файлова БД (app.db): користувачі, класи, набори, картки, завдання, прогрес, результати тестів.
Журнал запитів — файл request.log з записом HTTP-запитів для моніторингу та перегляду адміністратором.


3.2.3 Механізми взаємодії компонентів


Взаємодія між компонентами програмної системи здійснюється за клієнт-серверною моделлю з використанням REST API. Клієнтські модулі (веб-клієнт та IoT-клієnt) формують HTTP-запити до серверної частини, яка обробляє їх, виконує необхідні операції та повертає результат у вигляді HTTP-відповіді.
Передача даних між компонентами реалізована за протоколом HTTP. У локальному середовищі використовується протокол HTTP; при розгортанні системи в мережевому середовищі передбачається можливість застосування HTTPS для забезпечення захищеного обміну даними.
Формат обміну даними — JSON. Запити містять структуровані дані в тілі повідомлення (наприклад, параметри автентифікації, дані наборів слів, відповіді на тестові завдання). Відповіді сервера також передаються у форматі JSON. Для ідентифікації користувача після автентифікації застосовується механізм JWT-токена, що передається в HTTP-заголовку Authorization.
Взаємодія компонентів є синхронною: клієнт ініціює запит і очікує відповіді від сервера перед виконанням наступних дій інтерфейсу. Такий підхід забезпечує послідовність обробки даних, передбачуваність поведінки системи та спрощує реалізацію бізнес-логіки на серверному рівні.

3.2.5 UML діаграма розгортання


UML діаграма розгортання показує, на яких вузлах буде розміщено основні частини системи та як вони взаємодіють між собою. У системі виділено такі вузли: клієнтський пристрій користувача, IoT-клієнт, сервер застосунку та вузол зберігання даних.
На клієнтському пристрої запускається вебклієнт у браузері. IoT-клієнт використовується як спрощений навчальний пристрій. Дані системи зберігаються у SQLite Database, а HTTP-запити фіксуються у Request Log.

3.2.6 Використані принципи та патерни проєктування


У процесі розробки системи було використано принципи та патерни проєктування, які забезпечують зрозумілу структуру, підтримуваність і можливість подальшого розширення програмного забезпечення.
Основним принципом є розділення відповідальності. Система поділена на клієнтську частину, серверну логіку та рівень даних. Клієнт відповідає за інтерфейс користувача, сервер – за обробку запитів і бізнес-логіку, а база даних – за зберігання інформації.
Також використано принцип модульності. Серверна частина поділена на окремі модулі: авторизація, класи, набори слів, завдання, навчання, тести, статистика та адміністрування. Це спрощує підтримку коду та дозволяє змінювати окремі частини системи без впливу на всю програму.
Для уникнення дублювання використано принцип DRY. Спільна логіка винесена в допоміжні файли, зокрема middleware, helpers, limits та API-клієнт. Це дозволяє повторно використовувати код у різних частинах системи.
Також у системі застосовано такі патерни проєктування:
   * REST API — обмін даними між клієнтом і сервером здійснюється через 
API-ендпоінти з використанням методів GET, POST, PATCH та DELETE.
   * SPA (Single Page Application) — клієнтська частина працює як 
   * Router — кожен функціональний модуль має власний набір маршрутів для обробки запитів.
   * RBAC (Role-Based Access Control) — доступ до функцій системи визначається роллю користувача (учень, викладач, адміністратор).


3.2.7 Нефункціональні вимоги


   * Продуктивність. Система повинна забезпечувати швидку обробку запитів користувачів та коректну роботу основних функцій: авторизації, роботи з наборами слів, проходження тестів і перегляду статистики. Для підвищення продуктивності використовуються оптимізовані запити до бази даних та обмеження надмірної кількості запитів.
   * Масштабованість. Архітектура системи побудована модульно, що дозволяє додавати нові функції та розширювати наявні модулі без суттєвих змін інших компонентів. У разі збільшення кількості користувачів SQLite може бути замінена на серверну СУБД.
   * Надійність. Система повинна забезпечувати коректну обробку помилок та збереження цілісності даних. Для цього використовується перевірка вхідних даних, журналювання запитів і контроль виконання операцій із базою данихю
   * Безпека. Захист системи забезпечується автентифікацією користувачів за допомогою JWT, перевіркою ролей доступу, валідацією вхідних даних та обмеженням кількості запитів до сервера.


3.2.8 Аналіз ризиків та засоби захисту


Під час проєктування системи було визначено основні ризики та заходи щодо їх мінімізації.
Втрата даних може виникнути через помилки програмного забезпечення або пошкодження бази даних. Для зменшення ризику передбачено резервне копіювання даних та журналювання операцій.
Несанкціонований доступ може призвести до витоку або зміни інформації. Для захисту використовуються JWT-токени, перевірка ролей користувачів та обмеження доступу до функцій системи.
Помилки введення даних можуть спричинити некоректну роботу окремих функцій. Для їх запобігання виконується валідація даних як на клієнтській, так і на серверній стороні.
Перевантаження сервера може виникнути через велику кількість запитів або зловмисну активність. Для зниження цього ризику використовується механізм rate limiting та контроль навантаження на сервер.

3.4 Приклади використаних алгоритмів та методів
3.4.1 Алгоритм перемішування (метод Фішера — Йейтса)


Для випадкового впорядкування карток і варіантів відповідей використовується алгоритм Фішера — Йейтса. Алгоритм забезпечує рівноймовірне перемішування елементів масиву та має часову складність O(n). Його використання дозволяє уникнути повторюваного порядку запитань під час навчання та тестування.
export function shuffleArray(arr) {
  const a = arr.slice();
  for (let i = a.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [a[i], a[j]] = [a[j], a[i]];
  }
  return a;
}

3.6 Опис підготовки даних
3.6.1 Джерела даних


Основним джерелом даних у системі є інформація, що вводиться користувачами через вебінтерфейс. До таких даних належать реєстраційна інформація користувачів, назви класів, наборів слів, картки слів, завдання, результати тестування та статистика навчання. Додатково система може використовувати зображення карток, що задаються у вигляді URL-посилань.


3.6.2 Перевірка та очищення даних


Перед збереженням інформації в базі даних виконується перевірка коректності введених значень. Система перевіряє обов’язкові поля, довжину текстових значень, формат електронної пошти та допустимість ролей користувачів.
Текстові дані проходять базове очищення від зайвих пробілів та порожніх значень. Для перевірки відповідей учнів використовується нормалізація рядків: усі символи переводяться до нижнього регістру, а послідовності пробілів замінюються одним пробілом. Це дозволяє уникнути помилок, пов’язаних із різним написанням однакових слів.


3.6.3 Трансформація даних


Після перевірки дані перетворюються у формат, придатний для зберігання та обробки. Паролі користувачів хешуються перед записом у базу даних. Дати та часові мітки автоматично формуються сервером. Результати тестування перетворюються на числові показники, які використовуються для розрахунку статистики успішності.
Для навчальних карток система зберігає не лише слово та переклад, а й поточний стан вивчення (not_started, know, almost, repeat), що використовується під час формування індивідуального прогресу користувача.


3.6.4 Імпорт та збереження даних


Введені користувачем дані надходять до сервера через REST API у форматі JSON. Сервер виконує перевірку та обробку отриманих даних, після чого вони записуються до реляційної бази даних SQLite.
Під час створення наборів слів, карток, завдань або проходження тестів система автоматично формує відповідні записи у взаємопов’язаних таблицях бази даних. Для забезпечення цілісності використовуються первинні та зовнішні ключі.


3.6.5 Забезпечення якості даних


Для підтримки якості даних у системі використовуються механізми валідації, перевірка ролей користувачів, контроль унікальності окремих записів та обмеження доступу до операцій зміни даних. Використання централізованої обробки на сервері дозволяє запобігати появі некоректної або дубльованої інформації.

export function datetimeValue(iso) {
  const raw = String(iso || '').trim();

const CODE_CHARS = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789';


// унікальний код класу
export function generateClassCode() {
  const db = getDb();
  // пробуємо кілька разів, поки не вийде код, якого ще немає
  for (let attempt = 0; attempt < 20; attempt++) {
    let code = '';
    for (let i = 0; i < 6; i++) {
      const r = Math.floor(Math.random() * CODE_CHARS.length);
      code += CODE_CHARS[r];
    }
    const exists = db.prepare('SELECT id FROM classes WHERE class_code = ?').get(code);
    if (!exists) return code;
  }
  throw new Error('Не вдалося згенерувати код класу');
}


// знаходимо клас, який належить цьому викладачу
export function getClassForTeacher(classId, teacherId) {
  return getDb()
    .prepare('SELECT * FROM classes WHERE id = ? AND teacher_id = ?')
    .get(classId, teacherId);
}


// перевіряємо, чи учень є в класі
export function isStudentInClass(classId, studentId) {
  const row = getDb()
    .prepare('SELECT id FROM class_members WHERE class_id = ? AND student_id = ?')
    .get(classId, studentId);
  return !!row;
}


// беремо завдання разом з даними про клас і набір слів
export function getAssignmentById(assignmentId) {
  return getDb()
    .prepare(
      `SELECT a.*, c.teacher_id, c.title AS class_title,
       ws.title AS word_set_title, ws.language AS word_set_language
       FROM assignments a
       INNER JOIN classes c ON c.id = a.class_id
       INNER JOIN word_sets ws ON ws.id = a.word_set_id
       WHERE a.id = ?`,
    )
    .get(assignmentId);
}


// перевіряємо, чи має користувач доступ до завдання
export function canAccessAssignment(user, assignment) {
  if (!assignment) return false;
  if (user.role === 'teacher') return assignment.teacher_id === user.id;
  if (user.role === 'student') return isStudentInClass(assignment.class_id, user.id);
  return false;
}


// рахуємо статус завдання для учня
export function computeStudentAssignmentStatus(db, assignmentId, studentId) {
  // якщо є результат тесту — завдання завершене
  const test = db
    .prepare(
      'SELECT id FROM test_results WHERE assignment_id = ? AND student_id = ? LIMIT 1',
    )
    .get(assignmentId, studentId);
  if (test) return 'completed';


  // якщо учень уже працював зі словами — у процесі
  const progress = db
    .prepare(
      `SELECT COUNT(*) AS n FROM word_progress
       WHERE assignment_id = ? AND student_id = ? AND status != 'not_started'`,
    )
    .get(assignmentId, studentId);


  return (progress?.n || 0) > 0 ? 'in_progress' : 'not_started';
}


// перемішуємо масив
export function shuffleArray(arr) {
  const a = arr.slice();
  for (let i = a.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [a[i], a[j]] = [a[j], a[i]];
  }
  return a;
}
